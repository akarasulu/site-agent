# Sprint v1.15.0

Date: 2026-06-16

## Goal

Make the generated explorer easier for API consumers to understand by
organizing it around user intent and concrete examples instead of dense raw
artifact lists.

## Delivered

* Added role modes for Use, Automate, Audit, and Debug workflows.
* Added a Debug view for generated summary, artifact routing, and capability
  projection inspection.
* Added selected-operation examples for HTTP request bodies, curl, Python, MCP,
  Ansible, and Postman.
* Added selectable method rows so users can pivot from method lists to examples
  without opening the dense audit browser.
* Added argument schema and return schema metadata to `explorer-data.json` so
  browser examples can use typed sample values.
* Added Postman Web and official Postman import-documentation links to the
  explorer and generated Postman artifact helper pages.

## Validation

```bash
python -m pytest tests/unit/test_explorer.py tests/unit/test_cli_flow.py::test_cli_fixture_flow
python -m py_compile site_agent/core/explorer.py site_agent/cli.py
node --check /tmp/site-agent-explorer-js.js
```

Browser smoke validation against the regenerated ZTE explorer confirmed:

* Use mode shows Overview, API, and Postman tabs.
* Automate mode shows Python, MCP, and Ansible tabs.
* Audit and Debug modes show only their corresponding tabs.
* Selected-operation examples render for HTTP body, curl, Python, MCP,
  Ansible, and Postman.
* Postman Web and import-documentation links are present.
* Audit evidence remains collapsed by default.
* Mobile layout has no horizontal overflow.

## Notes

The explorer now separates consumer tasks from reviewer tasks:

* Use mode starts with Swagger, Postman, and copy-ready call examples.
* Automate mode focuses on Python, MCP, and Ansible.
* Audit mode keeps the UI evidence, adapter context, and rendered page
  snapshots for reviewers.
* Debug mode exposes generated summary and artifact-routing internals without
  putting that detail in the primary user path.
