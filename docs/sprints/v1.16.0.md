# Sprint v1.16.0

Date: 2026-06-16

## Goal

Expose Swagger-style interactive execution directly from the generated
explorer, while preserving dry-run safety and the existing Swagger UI path.

## Delivered

* Added `Try in Swagger` links for the selected explorer operation.
* Added OpenAPI operation metadata to `explorer-data.json`, including method
  path, operation ID, and Swagger tag.
* Added API bridge URL metadata to `explorer-data.json`.
* Added a native `Try Operation` panel with:
  * editable request JSON,
  * local API bridge URL configuration,
  * bridge health check,
  * dry-run execution,
  * guarded apply execution,
  * response rendering.
* Added CORS and `OPTIONS` handling to the local API bridge so browser-hosted
  Swagger UI and explorer Try requests can call the bridge.

## Validation

```bash
python -m pytest tests/unit/test_explorer.py tests/unit/test_http_api_bridge.py
python -m py_compile site_agent/core/explorer.py site_agent/core/synthesize/http_api.py
node --check /tmp/site-agent-explorer-js.js
```

Browser smoke validation against the regenerated ZTE explorer and live API
bridge confirmed:

* `http://127.0.0.1:8765/index.html` served the explorer.
* `http://127.0.0.1:8766/health` responded through the explorer Try panel.
* The selected operation exposed a `Try in Swagger` link.
* The native Try panel ran a dry-run request and rendered the JSON response.
* No browser console errors appeared during the interactive smoke.

## Notes

Interactive execution remains dry-run by default. Apply mode requires a user to
check the apply confirmation box, and non-low-risk operations trigger an
additional browser confirmation prompt.
